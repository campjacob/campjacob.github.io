I have gone through a bit of a quest looking at reference management software. I think I have written about this in other classes previously. I am a fan of technology and enjoy the software aspect of research along with the actual research. I am currently using [Bookends](https://www.sonnysoftware.com) by Sonny Software for my reference management software (think RefWorks, EndNote, Zotero, etc.). It is only on Mac / iOS, so it won't work for you if you use other platforms. I ended up on Bookends due to several factors:

1. It is more open than many of the other software in how it stores the data and specifically the PDFs of my journal articles/book chapters. I want to use whatever app to read and review those articles on either my Mac or my iPad. It does a great job of facilitating that.
2. The iPad implementation of most other applications is the primary reason I have gone with Bookends and felt that most of the other software let me down. Bookends iPad app is not very beautiful (neither is the Mac app), but it is very functional.
3. It offers more customizability and opportunities for automation than other apps seem to. I have to create some of my own systems, but it gives me more power than others, and I like that technical aspect. Because of this, I also have to sometimes spend more time than I did with other apps (like when I was with Zotero) in developing the stylesheet for my reference list entries.

For where I actually do my writing, I do not do that in Microsoft Word. Almost anything I write, it starts in another Mac/iOS app - [Drafts](https://getdrafts.com). This app is pretty amazing, and I use it for a lot of things. Any text that I start to write starts in Drafts (emails, shopping lists, random information,... etc.). It is highly customizable and allows you to process that text in a number of ways. I have a set of actions I use when I am doing academic writing that has a number of "tools" in it. These include a sorting button, a word count button (If you want to know how nerdy I am, I wrote a little Javascript thing that counts how many words any selected text is so I know if I need to make a quote a blockquote), it can export to HTML (which is how I post to Canvas), look up words in a thesaurus, or send the text to OneDrive and save it as a file so that I keep all the notes and writing for each of my classes in the same folders. It isn't "rich text," so in some ways, it is like "Notepad" or "TextEdit." To provide formatting, I use simple codes in what is called [Markdown](https://en.wikipedia.org/wiki/Markdown). This allows me to make things bold, italics, make links, or do other simple formatting. When I post into the forums, I have a short piece of HTML that includes making a section have a hanging indent, so my reference looks nice. The nice thing about Markdown is it is very human-readable and doesn't look like code. If I want to make a bulleted list, I write "* " and it will be able to be exported as an unordered list. If you want it to be italics, surround the word in an underscore (_).

All of this so far might have lost some of you, but I will say writing like this is pretty easy. I go further and do other kinds of crazy things. For example, I use a type of BibTeX for my citations. Especially for papers, I will copy a "temporary citation" from Bookends. This temporary citation looks something like the following:

```LaTeX

\textcite{Mitchell-et-al-2019-231726} describe many adverse long-term outcomes for students with emotional and behavioral disabilities. These include: (1)...

```

I write it in the BibTeX command so I remember what it needs to look like, but it doesn't have to be. I don't write my reference list or my in-text citations by hand (at least at first). I have to make sure that they all get exported correctly from Bookends. The benefit is, as I am editing my paper, I don't have to worry about making sure my in-text citations match my reference list. I generate my reference list as the last step in my writing. I can add new references and delete other ones.

I go through writing my initial draft and then go through it a couple of times. I will bounce back and forth between Drafts and [Grammarly](https://www.grammarly.com). If you don't use Grammarly, you might consider it. It has been a significant improvement for my writing. I often spend a substantial amount of time in the actual Grammarly app. I will usually write first in Drafts, and then I re-write a lot of what I wrote as I do a second or third pass. Once I feel like the writing is polished and finished, I copy and paste the text into Microsoft Word or Apple Pages. I tell Bookends to generate the reference list and update the temporary citations throughout my paper to be in-text citations. I have to go through them and make sure they are formatted correctly again, but it allows me to make sure that my in-text citations and reference list entries match. I then go back through my paper to make sure that the formatting everywhere is correct and looks good. I also do a quick review of the content before actually submitting my assignment.

That has been my process. The only other thing that I will say about large writing projects is to consider having a way to put things into sections. I find that when I break more extensive papers down into smaller units, it is helpful. I can have links to each of the little mini documents and see it all together (in Drafts), but it is nice to have little buckets of text to focus. This is similar if you write in something like Scrivener or Ulysses.
